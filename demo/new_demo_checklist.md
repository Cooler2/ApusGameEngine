# New Demo Checklist

Use this checklist when adding or modernizing a demo. It keeps FPC, Delphi, and
the demo group project in sync.

## Required Files

- `demo/<DemoName>/<DemoName>.dpr`
- one main scene/app unit, usually `MainScene.pas`, `<DemoName>App.pas`, or
  `Scene<DemoName>.pas`
- `demo/<DemoName>/<DemoName>.dproj`
- tracked resources required at compile time or runtime

Avoid unconditional `{$R *.res}` unless the matching `.res` file is tracked and
required. Most maintained demos do not need it.

## DPR Rules

- Add FPC/Unix `cthreads` first in `uses`:

```pascal
uses
  {$IFDEF FPC}{$IFDEF UNIX}cthreads,{$ENDIF}{$ENDIF}
  MainScene in 'MainScene.pas';
```

- Create, prepare, run, and free the application explicitly:

```pascal
begin
  application:=TMainApp.Create;
  application.Prepare;
  application.Run;
  application.Free;
end.
```

## DPROJ Rules

Use a maintained demo `.dproj` as the baseline. `NormalMap.dproj`,
`StyleDemo.dproj`, and `UIScaleDPI.dproj` are current compact examples.

Required settings:

- `MainSource` points to `<DemoName>.dpr`
- unique `ProjectGuid`
- `ProjectName` and `SanitizedProjectName` match the demo name
- Win32 and Win64 platforms are enabled
- `DCC_UnitSearchPath` includes:
  - `..\..`
  - `..\..\extra`
  - `..\..\base`
  - `..\..\base\extra`
  - `..\..\extra\sdl2`
- `DCC_Define` includes `DELPHI;OPENGL;LODEPNG;FREETYPE`
- executable output:
  - Win32: `..\..\bin`
  - Win64: `..\..\bin64`
- DCU output: `..\..\units`
- Debug config keeps range/integer checks enabled where practical
- `DCCReference` includes the main scene/app unit

Delphi builds are manual-only. Do not run Delphi from automation; just keep the
project file ready and XML-valid.

## Group Project Rules

Update `demo\demos.groupproj` in the same change:

- add `<Projects Include="<DemoName>\<DemoName>.dproj">`
- add `<Target Name="<DemoName>">`
- add `<Target Name="<DemoName>:Clean">`
- add `<Target Name="<DemoName>:Make">`
- add the three target names to aggregate `Build`, `Clean`, and `Make`

Then run:

```bat
demo\validate_demo_group.cmd
```

The helper must pass before the demo is considered integrated.

## FPC Validation

Build through the wrapper:

```bat
cmd /c demo\build_demo_fpc.cmd <DemoName>
```

If the build discovers an existing demo problem while integrating metadata, fix
the small local issue or record the blocker. Do not mark the demo integrated if
the wrapper cannot build it and no explicit blocker is documented.

Common problems:

- linked scrollbars require `TUIScrollable`, not a plain `TUIElement`
- missing `.res` files caused by unconditional `{$R *.res}`
- stale `_fpc` files after switching compiler defines
- `.dproj` paths drifting from the group project

## Runtime Validation

Do not run a produced `.exe` unless the user explicitly asks. If runtime
validation is requested, prefer Robot API for a launch/capture/exit smoke check.

For file-based Robot API requests, send commands sequentially because
`robot_in.txt` and `robot_out.txt` are shared per process working directory.

## Cleanup and Git

- Keep FPC outputs in demo-local `_fpc` or configured output folders.
- Use `demo\cleanup.bat dry-run` to preview ignored demo artifacts.
- Do not add `.dproj.local`, `*.res` generated by the IDE, `_fpc`, logs, or
  runtime Robot API files.
- Keep problem-knowledge notes under `Work/` local/ignored unless explicitly
  asked to commit them.
